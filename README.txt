Turnstile 保護（舊網址導向 + 新站登入/註冊）
============================================
只需要一個檔案（取代上一版同名檔案）：

  functions/_middleware.js

安裝
1. 放進專案 functions/ 資料夾（與 [[path]].js 同層），commit 並 push 到 main。
2. Cloudflare Turnstile 小工具的網域加入：
     coffee1688.pages.dev
     member.ytgp168.com
     www.member.ytgp168.com
3. Pages > 設定 > 變數和密碼：
     TURNSTILE_SITE_KEY = Site key （一般變數）
     TURNSTILE_SECRET   = Secret key（Secret）
   修改後需重新部署。

受保護範圍
- POST /api/member/login、/api/member/send-email-code、/api/member/register、/api/admin/login
  → 後端沒有有效 token 一律回 403。
- 前端：/member、/member/register、/admin 頁面自動注入驗證腳本，送出時才驗證
  （平常不顯示，必要時才跳出勾選框）。

行為
- 兩個金鑰任一沒設定 → 新站保護不啟用（不會把自己鎖在外面）。
- 舊網址 coffee1688.pages.dev：首頁顯示更新通知，其他路徑轉到新網址同路徑。

部署後請依序測試：會員登入、註冊（含寄驗證碼）、/admin 登入。
若出問題，刪掉 TURNSTILE_SECRET 重新部署即可關閉保護。

==================== v39：直播下單（TikTok 直播留言「A201+1」） ====================
【升級步驟】
1. 先在 D1 執行一次資料庫升級（全新安裝用最新 schema.sql 則不需要）：
   wrangler d1 execute test2 --remote --file=./migrate_v19.sql
2. 重新部署整個專案（functions/ 與 public/ 一起上傳）。
3. 後台新增「直播下單」分頁；會員管理多了「TikTok 帳號」欄位。

【運作方式】不連線 TikTok、不需要電腦或 VPS，全部在後台操作。
- 會員資料填 TikTok 帳號（不分大小寫、@ 可有可無；同一帳號只能綁一位會員）。
- 直播前：直播下單 → 新增場次 → 新增商品（代號例如 A201、名稱、單價、庫存；庫存留空 = 不限量）。
  新增場次時可以複製上一場的商品清單。
- 直播中：把留言貼進「貼上直播留言」，一行一則，格式「TikTok 帳號 代號+數量」：
    @xiaoming A201+1
    @ahua a201 +2
    @someone A201+1 A202+2      （一則留言可有多個商品）
  代號不分大小寫、+ 前後空格都可以。
- 系統自動解析並歸戶，狀態有：
    已歸戶（TikTok 帳號對得到會員）／未綁定（對不到會員）／非會員／候補（超過庫存）／無效（代號不存在、格式錯誤）／已建單
- 未綁定：可「歸給會員」（預設會記住這個 TikTok 帳號，之後自動歸戶，同帳號的其他未綁定留言一併處理），
  或「當非會員」。事後補了會員的 TikTok 帳號，按「重新比對會員」即可。
- 候補：按「改為正式」可手動轉正式（不會再檢查庫存）。
- 「建立訂單並產生連結」：已歸戶與非會員的留言，同一人合併成一張訂單，沿用原本的 3 小時結帳連結；
  訂單備註會自動寫上場次、TikTok 帳號與商品明細。未綁定與候補不會建單。
- 建單後可逐筆複製連結，或「複製全部連結」（格式：@帳號 金額 連結）。
- 結標後不能再貼留言；可「重新開啟」。刪除場次不會刪除已建立的訂單。

==================== v54：員工權限（只有管理員能設定員工） ====================
【升級步驟】
1. D1 執行一次升級：wrangler d1 execute <你的資料庫名稱> --remote --file=./migrate_v22.sql
   （全新安裝用最新 schema.sql 則不需要）
2. 重新部署整個專案。
   - 沒執行 migrate_v22.sql 就先部署也不會壞：系統會維持舊行為（所有帳號都當管理員），執行後才開始限制。

【角色】
- 管理員（owner）：帳號名稱是 admin 的帳號；如果沒有叫 admin 的帳號，就是最早建立的那個帳號。
  可以做所有事，包含新增員工、設定權限、重設密碼、刪除員工。管理員帳號不能被刪除。
- 員工（staff）：只能使用被勾選的功能；沒有任何路徑可以進入「員工帳號」分頁或修改任何權限。

【可勾選的功能】
首頁／結帳櫃檯與訂單列表／永久刪除訂單／會員管理／刪除會員／儲值統計與資料匯出／付款設定與系統公告／費率設定／優惠碼／點數系統／直播下單／操作紀錄
- 「永久刪除訂單」要先有「結帳櫃檯／訂單列表」；「刪除會員」要先有「會員管理」（介面會自動連動勾選）。
- 結帳櫃檯、直播下單、點數系統需要挑選會員，所以有這些權限的員工可以「讀取」會員名單，但不能新增、修改或刪除會員。
- 員工登入後，沒有權限的分頁不會顯示；就算直接呼叫 API，伺服器也會回 403。

【現有員工】
- 升級後，既有員工的權限是「尚未設定」，維持升級前的行為（全部功能，但不含員工帳號管理），員工帳號列表會用紅字標示。
  請到「員工帳號」分頁按「設定權限」逐一確認。
- 想升級後一次改成只能用「首頁＋結帳櫃檯／訂單列表」，可以執行 migrate_v22.sql 裡被註解掉的最後一行。
- 新增員工時預設勾選「首頁」與「結帳櫃檯／訂單列表」。

【其他】
- 權限每次請求都從資料庫讀取：管理員改了權限，員工下一次操作就生效；員工帳號被刪除，下一次操作就會被登出。
- 新增員工、設定權限、刪除員工都會寫進「操作紀錄」。

==================== 結帳櫃檯：品項明細輸入 ====================
結帳櫃檯「建立結帳連結」表單新增「品項明細」區：
  - 每列：品名、數量、單價（小計自動計算），可「＋ 新增品項」或按 × 移除。
  - 金額來源可選：
      「手動輸入金額」：金額自己填，品項只當明細紀錄（兩者不必相等）。
      「由品項自動加總」：金額欄鎖定，自動 = Σ(數量 × 單價)；後端會重新計算，以後端結果為準。
  - 建立訂單成功後，品項會自動寫入 order_items（同一批寫入），
    之後在「訂單列表」的品項明細面板就看得到，可繼續編輯、標記交貨、寄送明細。

【一、訂單操作歷程】
- 後台 → 訂單列表，每一列多一顆「紀錄」按鈕，打開這張訂單的時間軸：誰、什麼時候、做了什麼
  （建單、客人選付款方式／上傳證明、標記付款、更正、結案、備註、品項新增修改刪除與交貨、寄明細…）。
- 「更正訂單」會記下修改前→修改後，例如「金額: $500 → $600；付款方式: 轉帳 → 超商條碼」。平台密碼等敏感內容不會記錄。
- 「匯出 CSV」：這張訂單的完整歷程（UTF-8 含 BOM，Excel 直接開；檔名 order_TW210001_history.csv）。
  匯出本身也會留一筆紀錄。
- 權限：沿用「訂單列表」（拆分後的 order_list），不需要「操作紀錄」權限。
- 資料來源：操作紀錄裡 order_id 等於這張訂單的紀錄；舊紀錄（沒有 order_id）用訂單編號文字比對（編號後面不能緊接數字，
  避免 TW210003 比對到 TW2100031，且只找訂單建立之後的紀錄）；紀錄裡缺少的重要時間點（建立、付款、結案、過期…）
  用訂單本身的時間欄位補上，畫面標示「由訂單資料推算」。
- 資料庫：admin_logs 新增 order_id 欄位與索引（migrate_v25.sql；schema.sql 已包含）。
  品項的修改／刪除／交貨也會歸到所屬訂單。操作歷程不提供匯入（稽核資料不該能被匯入改寫）。

【二、資料備份／還原（只有管理員）】
- 後台 → 資料備份。
  下載備份：把所有資料表整份下載成一個 .json 檔（動態讀取資料庫實際有的資料表，之後新增資料表也不會漏）。
    · 可選：包含操作紀錄、包含後台帳號（含密碼雜湊）、包含付款證明截圖與條碼圖片（預設不含，檔案會小很多）。
    · 強烈建議設定「備份檔密碼」：AES-256-GCM 加密（密碼經 PBKDF2-SHA256 20 萬次運算），在瀏覽器完成，密碼不會送到伺服器。
      忘記密碼就無法還原，也無法找回。沒設定密碼時下載前會跳警告（檔案裡有會員個資、客人填的平台密碼、系統金鑰）。
    · 頁面會顯示「上次備份」時間，超過 7 天會提醒。建議每週下載一次、存放在這台電腦以外的地方。
  還原備份：選檔 →（有加密就輸入密碼）→「讀取備份檔」→ 先看摘要（備份時間、每張資料表備份筆數／目前筆數／是否可還原）
    → 選方式 → 輸入確認文字 →「開始還原」。
    · 補回缺少的資料：只補目前沒有的資料（以編號判斷），不修改、不刪除現有資料。適合救回誤刪的資料。確認文字：還原
    · 全部覆蓋：把資料表整張換成備份內容，備份之後新增的資料會消失。適合回到某個時間點或搬到全新資料庫。確認文字：覆蓋
    · 還原前預設會自動下載一份「目前資料」的備份（含圖片；備份檔有加密時沿用同一個密碼加密），萬一還原錯了可以用它救回來。
    · 後台帳號：預設不還原；勾選後只會「覆寫編號相同的帳號」，不會刪除任何現有帳號，也不會動到目前登入的這個帳號。
    · 操作紀錄：永遠只補不覆蓋、不清空。編號被別筆紀錄佔用時改發新編號保留；內容相同的重複紀錄會跳過，重複還原不會越還越多。
    · 備份不含暫時性資料：email_codes（驗證碼）、email_send_log（寄信節流）、push_subscriptions（裝置推播訂閱）。
    · 備份檔含 settings（系統設定，包含直播監聽金鑰等）。全部覆蓋會一併換回備份當時的設定。
    · 備份檔的欄位比目前資料庫多（備份來自較新版本）時會明確擋下，請先升級程式與資料庫再還原。
- 運作方式：瀏覽器分批（每批數百筆）向伺服器讀寫，單一請求很小，不會碰到 Cloudflare 的時間／記憶體上限；
  含圖片時每批只讀 10 筆。資料量很大時下載需要一點時間，畫面有進度條，請不要關閉分頁。
- 安全：資料表與欄位名稱一律先跟資料庫實際結構比對才使用；其餘值都走綁定參數；每批最多 500 筆、90 個欄位；
  所有 /api/admin/backup/* 預設只有管理員（員工即使勾滿所有權限也是 403）。
  下載與還原都會寫入操作紀錄（類別「資料匯出」：data.backup_export / data.backup_restore / data.backup_clear）。
- 目前沒有「自動排程備份」：Cloudflare Pages 本身不能定時執行，之後可以用你現有的 GitHub Actions（跟每日營運日報一樣的做法）
  加一支排程，把加密後的備份存到 Cloudflare R2；需要的話再說。

異動檔案：migrate_v25.sql（新）、schema.sql、functions/_lib/backup.js（新）、functions/_lib/helpers.js、
          functions/[[path]].js、functions/_lib/templates.js、README.txt


==================== v63：會員詳細頁（標籤、備註紀錄、封鎖下單） ====================
【升級步驟】
1. D1 執行一次升級：wrangler d1 execute <你的資料庫名稱> --remote --file=./migrate_v26.sql
   （全新安裝用最新 schema.sql 則不需要；注意是 migrate_v26.sql，v24、v25 是前面版本的升級檔）
2. 重新部署整個專案。
   - 沒執行 migrate_v26.sql 就先部署也不會壞：會員列表、詳細頁照常可看，標籤、備註、封鎖下單會提示先升級；
     在升級之前，封鎖下單的檢查不會生效。

【怎麼用】
- 後台「會員管理」→ 點會員的姓名（或「詳細」按鈕）進入會員詳細頁，上方「← 返回會員列表」回到列表。
- 基本資料：帳號、TikTok、電話、信箱、推薦碼、推薦人、已推薦人數、加入時間、備註；可直接進入編輯與設定密碼。
- 消費總覽：累計消費（已付款）、已付款筆數、平均每筆、本月消費（台灣時間）、最近一次下單、進行中訂單、逾期／取消筆數、點數餘額。
- 訂單歷史（最近 50 筆）：每筆可按「查看」跳到訂單列表並搜尋該訂單（需要訂單列表權限）。
- 點數紀錄（最近 30 筆）與累計獲得／使用點數。
- 標籤：預設快速按鈕 VIP、老客戶、需注意、黑名單，也可自訂（最多 10 個、每個最多 12 個字）；按「儲存標籤」才生效。
  會員列表的姓名下方會顯示標籤，搜尋框也可以用標籤文字搜尋。
- 備註紀錄：可新增多則備註，每則記錄時間與寫的人，可刪除。
- 下單封鎖：填寫原因（只有後台看得到）後封鎖；可隨時解除。

【封鎖下單的效果】
- 會員自助下單：回覆「您的帳號目前無法下單，如有疑問請聯絡客服」；會員頁的「建立訂單」按鈕會停用並顯示同樣的說明。
  會員仍可登入、查看訂單與點數；封鎖前已建立的訂單與付款連結不受影響。
- 後台結帳櫃檯：替被封鎖的會員建立訂單會被擋下並顯示原因，要先到詳細頁解除封鎖。
- 直播下單：被封鎖會員的留言狀態是「已封鎖」，只記錄、不佔庫存、不會建單；
  「歸給會員」或「重新比對會員」遇到被封鎖的會員時也會標成「已封鎖」。
- 「黑名單」標籤只是標記，不會自動封鎖；要擋下單請另外按「封鎖下單」。

【權限】
- 看詳細頁、編輯標籤、新增或刪除備註：需要「會員管理」權限。
- 封鎖／解除封鎖：新增獨立權限「封鎖／解除封鎖會員下單」（需先有「會員管理」）。
  已經設定過權限清單的員工預設沒有這一項，請到「員工帳號」→「設定權限」勾選；管理員與「尚未設定」的員工維持原本的全部功能。
- 刪除整個會員仍是「刪除會員」權限；刪除會員時會一併刪除他的備註紀錄。
- 標籤、備註、封鎖與解除封鎖都會寫進「操作紀錄」。

【其他修正】
- 會員列表的姓名、帳號、電話、信箱、備註原本是直接輸出到頁面，名稱含 HTML 字元時可能被當成網頁內容執行；
  現在全部改成文字輸出（這是自助註冊可能被利用的地方，建議一併部署）。

==================== v66：多家轉帳銀行 + 超商三家分開開關 ====================
