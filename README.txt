Turnstile 保護（舊網址導向 + 新站登入/註冊）
============================================
只需要一個檔案（取代上一版同名檔案）：

  functions/_middleware.js

安裝
1. 放進專案 functions/ 資料夾（與 [[path]].js 同層），commit 並 push 到 main。
2. Cloudflare Turnstile 小工具的網域加入：
     coffee1688.pages.dev
     member.ytgp168.com
     www.member.ytgp168.com
3. Pages > 設定 > 變數和密碼：
     TURNSTILE_SITE_KEY = Site key （一般變數）
     TURNSTILE_SECRET   = Secret key（Secret）
   修改後需重新部署。

受保護範圍
- POST /api/member/login、/api/member/send-email-code、/api/member/register、/api/admin/login
  → 後端沒有有效 token 一律回 403。
- 前端：/member、/member/register、/admin 頁面自動注入驗證腳本，送出時才驗證
  （平常不顯示，必要時才跳出勾選框）。

行為
- 兩個金鑰任一沒設定 → 新站保護不啟用（不會把自己鎖在外面）。
- 舊網址 coffee1688.pages.dev：首頁顯示更新通知，其他路徑轉到新網址同路徑。

部署後請依序測試：會員登入、註冊（含寄驗證碼）、/admin 登入。
若出問題，刪掉 TURNSTILE_SECRET 重新部署即可關閉保護。


==================== v23：點數系統 ====================
【升級步驟】
1. 先在 D1 執行一次資料庫升級（全新安裝用最新 schema.sql 則不需要）：
   wrangler d1 execute <資料庫名稱> --remote --file=./migrate_v14.sql
   （本專案 wrangler.toml 的資料庫名稱是 test2）
2. 重新部署整個專案（functions/ 與 public/ 一起上傳）。
3. 登入後台 → 新的「點數系統」分頁，確認規則後按儲存。

【點數功能可個別開關】後台「點數規則」分成三塊，各自獨立：付款回饋（發點）、訂單折抵、點數商城。
只想開其中幾個就只勾那幾個；關閉的功能，對應欄位填什麼都不影響。

【預設規則（後台可改）】
- 訂單標記「已付款」時，依實付金額每 100 元給 1 點（無條件捨去）。
- 1 點折抵 1 元；單筆訂單最多可用點數折抵 50%。
- 訂單取消、刪除、改會員或更正金額時，回饋點數自動扣回／調整；
  訂單取消或過期時，已折抵的點數自動退回。

【會員端】會員頁新增「我的點數」：餘額、點數商城兌換、兌換紀錄、點數明細；
自助下單時可輸入要使用的點數（「最多可用」按鈕可一鍵填入）。

【後台】點數系統分頁：規則設定、兌換單處理（標記完成／拒絕並退點）、
商城商品管理、會員點數列表與手動加減點（必填原因）。


==================== v23 追加：會員自行修改手機 / 信箱 ====================
- 會員頁點名字展開「個人資料」→「修改手機 / 信箱」。
- 手機：09 開頭共 10 碼，可直接修改。
- 信箱：改成新信箱時，要先按「寄送驗證碼」，驗證碼會寄到「新信箱」，輸入正確才會更新，並標示「已驗證」。
  只接受常見信箱（Gmail、Outlook、Hotmail、Yahoo、iCloud 等），且不能與其他會員重複。
  寄送頻率限制與註冊相同（同信箱 60 秒冷卻、每小時 5 次）。
- 若 EMAIL_VERIFY_ENABLED 設為 "0"（關閉信箱驗證），改信箱不需要驗證碼，但不會標示「已驗證」。
- 姓名、帳號仍由店家在後台修改。
- 這次沒有資料庫變動，直接重新部署即可。


==================== v23 追加：登入後的「最新更新」提醒 ====================
- 會員頁最上方（我的推薦碼下方、第二張卡片）：有訂單或兌換單狀態變化時，才會出現「最新更新」卡片。
- 會提醒的變化：條碼已準備好、已完成付款、已結案、已取消、已過期，以及點數兌換被店家完成或拒絕（退點）。
- 按「知道了」後消失；之後有新的變化才會再出現。頁面開著時，訂單約 5 秒、兌換單約 30 秒自動更新。
- 「已看過」的記錄存在該手機 / 瀏覽器（localStorage），所以換手機或清除瀏覽器資料後，第一次登入不會把舊訂單全部跳出來，只會提醒之後的新變化。
- 沒有資料庫變動，直接重新部署即可。

- 後台「點數系統」→「會員點數」：新增搜尋欄，可用姓名、帳號、手機、信箱搜尋；列表一次顯示 10 位，按「顯示更多」再載入。

- 沒有資料庫變動，直接重新部署即可。


==================== v39：直播下單（TikTok 直播留言「A201+1」） ====================
【升級步驟】
1. 先在 D1 執行一次資料庫升級（全新安裝用最新 schema.sql 則不需要）：
   wrangler d1 execute test2 --remote --file=./migrate_v19.sql
2. 重新部署整個專案（functions/ 與 public/ 一起上傳）。
3. 後台新增「直播下單」分頁；會員管理多了「TikTok 帳號」欄位。

【運作方式】不連線 TikTok、不需要電腦或 VPS，全部在後台操作。
- 會員資料填 TikTok 帳號（不分大小寫、@ 可有可無；同一帳號只能綁一位會員）。
- 直播前：直播下單 → 新增場次 → 新增商品（代號例如 A201、名稱、單價、庫存；庫存留空 = 不限量）。
  新增場次時可以複製上一場的商品清單。
- 直播中：把留言貼進「貼上直播留言」，一行一則，格式「TikTok 帳號 代號+數量」：
    @xiaoming A201+1
    @ahua a201 +2
    @someone A201+1 A202+2      （一則留言可有多個商品）
  代號不分大小寫、+ 前後空格都可以。
- 系統自動解析並歸戶，狀態有：
    已歸戶（TikTok 帳號對得到會員）／未綁定（對不到會員）／非會員／候補（超過庫存）／無效（代號不存在、格式錯誤）／已建單
- 未綁定：可「歸給會員」（預設會記住這個 TikTok 帳號，之後自動歸戶，同帳號的其他未綁定留言一併處理），
  或「當非會員」。事後補了會員的 TikTok 帳號，按「重新比對會員」即可。
- 候補：按「改為正式」可手動轉正式（不會再檢查庫存）。
- 「建立訂單並產生連結」：已歸戶與非會員的留言，同一人合併成一張訂單，沿用原本的 3 小時結帳連結；
  訂單備註會自動寫上場次、TikTok 帳號與商品明細。未綁定與候補不會建單。
- 建單後可逐筆複製連結，或「複製全部連結」（格式：@帳號 金額 連結）。
- 結標後不能再貼留言；可「重新開啟」。刪除場次不會刪除已建立的訂單。

==================== v41：會員自行綁定 TikTok 帳號 ====================
- 會員頁點名字展開「個人資料」→ 新增「TikTok 帳號」：未綁定時可自己輸入（@ 可有可無、不分大小寫）並按「綁定」。

  （TikTok 沒有帳號歸屬驗證，鎖定是為了避免有人亂綁別人的帳號或綁了又改來搶單。）

==================== v43：直播留言自動抓取（選用） ====================
【升級步驟】
1. D1 執行一次升級：wrangler d1 execute test2 --remote --file=./migrate_v20.sql
2. 重新部署整個專案。
3. 後台「直播下單」最下面新增「自動抓取留言（選用）」：產生金鑰、取得接收網址。
4. 監聽程式在 listener/ 資料夾（安裝與執行方式見 listener/README.md）；
   不想用自己的電腦時，可用 .github/workflows/live-listener.yml 在 GitHub Actions 手動啟動（單次最長約 6 小時）。

【運作方式】
- 監聽程式連上直播間，只把符合「代號+數量」的留言送到 POST /api/live/ingest（標頭 X-Ingest-Key 驗證）。
- 留言會進到「最新一個開標中的場次」，後續歸戶、庫存、候補、建單規則和手動貼上完全相同；同一則留言重送不會重複寫入。
- 後台直播下單頁面在場次開標時每 5 秒自動更新留言清單。
- 重設金鑰後，舊金鑰立刻失效。
- 注意：TikTok 沒有官方的直播留言 API，監聽程式用的是非官方套件，可能隨 TikTok 改版而失效；程式沒有在真實 TikTok 直播間測試過。


==================== v44：費率只給「會員」看（修正） ====================
- 沒有資料庫變動，直接重新部署即可。
- /api/rates 之前允許「會員或後台管理員」，如果同一個瀏覽器有登入後台，首頁即使顯示未登入也會看到費率。
  現在只認會員登入；只登入後台、沒登入會員的人也看不到。回應加上 Cache-Control: no-store，避免被快取。
- 測試方式：用無痕視窗開 https://你的網址/api/rates ，應該看到「請先登入會員，才能查看費率」。
