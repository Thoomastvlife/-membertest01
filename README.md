# 會員結帳系統（Cloudflare Pages + D1 版）

跟 Workers 版功能相同，並新增：
- 會員資料新增「帳號」「密碼」欄位（密碼加鹽雜湊儲存；帳號可留空，不強制會員一定要有登入帳密）
- 後台新增「儲值統計」頁籤：選擇月份後，依會員（或非會員名稱）列出當月**已完成付款**訂單的筆數與金額合計
- **訂單更正**：後台訂單列表可修正打錯的金額、會員、付款方式（已取消或已結案的訂單不能再更正）
- **訂單完成（結案）標記**：訂單「已完成付款」後，可再手動點「訂單完成」多打一個結案標記，方便篩選哪些訂單已經處理完畢，**不影響金流本身**；可隨時取消結案再更正
- **付款證明上傳**：前台付款頁（轉帳、超商條碼）新增「上傳截圖 / 填寫帳號末幾碼」表單，客人送出後後台訂單列表會顯示縮圖與末幾碼，方便核對款項
- **前台會員自助查詢**：新增 `/member` 頁面，會員可用帳號密碼登入查詢自己的訂單記錄與付款狀態（帳密仍由後台「會員管理」建立/重設）
- 前台付款頁改為在訂單尚未結束前持續每 5 秒自動輪詢，店家在後台的操作（例如上傳條碼、標記已付款）會自動反映到客人畫面，不用手動重新整理
- **本次新增**：
  - 訂單列表新增「查看連結」按鈕，隨時可以重新取得某筆訂單的前台付款連結（**到期時間不會因為查看而改變，仍是建立當下起算 3 小時**）
  - 訂單列表新增「刪除」按鈕：徹底移除該筆訂單記錄，無法復原（跟「取消」不同，取消只是改狀態、記錄還留著）
  - 會員管理新增「編輯」按鈕：姓名、電話、備註、帳號都可以隨時修改；如果同時想改密碼，在編輯畫面的密碼欄位輸入新密碼即可（留空表示不變更密碼）
  - 以上功能不需要跑新的資料庫升級腳本，沿用既有的 D1 資料表結構即可
- **再次新增**：
  - 後台新增「員工帳號」頁籤：登入後可以新增其他管理員（員工）帳號、重設任何帳號的密碼、刪除帳號。員工帳號權限跟原本的管理員帳號完全相同（沒有分層級）。無法刪除「目前登入中」的那組帳號，也不能把所有帳號都刪光（至少要保留一組），避免不小心把自己鎖在外面。第一組帳號仍然是照原本流程，第一次打開 `/admin` 直接輸入帳密建立。
  - 付款連結新增「兩層」時效，分開設定（`wrangler.toml` 的 `[vars]`）：
    - `LINK_TTL_HOURS`（預設 `3`）：**付款時效**。訂單建立後幾小時內可以完成付款，超過就自動變成「已過期」，客人不能再繼續選付款方式或付款，但連結網址還打得開（會顯示已過期）。
    - `LINK_HARD_EXPIRE_HOURS`（預設 `24`）：**連結本身的失效時間**。訂單建立超過這個時數之後，不管訂單目前是什麼狀態，連結一律完全失效（打開會直接顯示「此付款連結已失效，請洽店家重新開立」），無法再查看任何資訊。這個時間到了以後，即使後台按「查看連結」重新取得網址，一樣是失效的，需要用「更正」改資料或建立新訂單。

## 檔案結構
```
member-checkout-pages/
├── wrangler.toml         # Pages 專案設定（含 D1 binding）
├── schema.sql            # 全新安裝用的資料庫結構
├── migrate_v2.sql        # 若你之前已用 Workers 版部署過，跑這個來升級既有資料庫
├── migrate_v3.sql        # 既有 D1 資料庫升級：新增訂單更正/結案/付款證明所需欄位（跑過 v2 的都要再跑這個）
├── migrate_v4.sql        # 既有 D1 資料庫升級：新增後台推播通知所需資料表
├── migrate_v5.sql        # 既有 D1 資料庫升級：新增會員推薦碼 + 隱藏自助註冊連結所需欄位
├── migrate_v6.sql        # 既有 D1 資料庫升級：新增優惠碼功能所需資料表與訂單欄位
├── public/
│   └── robots.txt        # 純佔位檔案，讓 Pages 的靜態輸出資料夾不是空的
└── functions/
    ├── [[path]].js       # 攔截所有路徑的主要邏輯（路由、API、頁面）
    └── _lib/
        ├── helpers.js    # 共用工具（登入驗證、密碼雜湊、cookie 簽署等）
        └── templates.js  # 後台 / 前台的 HTML 頁面
```
> `_lib` 資料夾開頭有底線，Cloudflare Pages 慣例會排除它不當作路由，但檔案仍可以正常被 import 使用。

## 部署步驟

1. 安裝 wrangler（若尚未安裝）
   ```
   npm install -g wrangler
   wrangler login
   ```

2. 建立 D1 資料庫（若是從 Workers 版升級，直接沿用原本的資料庫即可，不用重建）
   ```
   wrangler d1 create checkout_db
   ```
   把輸出的 `database_id` 貼到 `wrangler.toml`。

3. 建立資料表
   - 全新安裝：
     ```
     wrangler d1 execute checkout_db --file=./schema.sql
     ```
   - 從 Workers 版升級既有資料庫（沒跑過 v2 的話）：
     ```
     wrangler d1 execute checkout_db --file=./migrate_v2.sql
     ```
   - 任何既有資料庫，只要還沒有「訂單更正 / 結案 / 付款證明」這批新欄位，都要再跑一次：
     ```
     wrangler d1 execute checkout_db --file=./migrate_v3.sql
     ```

4. 建立 Pages 專案並設定機密值
   ```
   wrangler pages project create member-checkout-pages
   wrangler pages secret put ADMIN_SESSION_SECRET --project-name=member-checkout-pages
   ```

5. 部署
   ```
   wrangler pages deploy public --project-name=member-checkout-pages
   ```
   （`functions/` 資料夾會被 wrangler 自動一併打包部署，不需要另外處理）

6. 如果 D1 binding 沒有透過 `wrangler.toml` 自動生效，也可以到 Cloudflare Dashboard →
   Pages 專案 → Settings → Functions → D1 database bindings，手動把 `DB` 綁定到 `checkout_db`。

7. 部署完成後開啟 `https://你的網域/admin`：
   - 第一次會顯示「尚未建立任何管理員帳號」，直接輸入想要的帳號密碼即可完成建立。
   - 先到「付款設定」填入轉帳帳戶資訊，再開始使用「結帳櫃檯」「會員管理」「儲值統計」等功能。

## 「儲值統計」的計算邏輯
統計範圍是**該月份已經被後台標記為「已完成付款」的訂單**（也就是 `paid_at` 落在所選月份內），
依會員分組加總金額與筆數；非會員則依訂單建立時填的名稱分組（同名會歸在一起）。
如果之後想改成「以訂單建立時間」而非「付款完成時間」來統計，可以在
`functions/[[path]].js` 的 `handleMonthlyStats` 函式裡把 `paid_at` 改成 `created_at` 即可。

## 會員自助下單（本次新增）
`/member` 頁面登入後新增「自助下單」區塊：會員自己輸入金額按「建立訂單」，
系統會用該會員身分建立一筆新訂單（跟後台「結帳櫃檯」建立的訂單資料結構完全相同），
並給一個 `/pay/{token}` 付款連結，會員可自行前往選付款方式、上傳付款證明，
流程與時效（`LINK_TTL_HOURS` / `LINK_HARD_EXPIRE_HOURS`）都跟既有訂單一致。
「我的訂單記錄」列表也新增「操作」欄，未完成的訂單可點「前往付款」隨時回去繼續，
已完成/取消/過期的訂單則可點「查看」回顧當時頁面。
後台看到的訂單來源目前無法區分是店家建立還是會員自助建立（都會顯示在同一個訂單列表），
如果之後想加以區分，可以在 `orders` 資料表加一個 `created_by` 欄位並在 `handleMemberCreateOrder` / `handleCreateOrder` 分別寫入。

## 後台推播通知（本次新增）
會員在 `/member` 自助下單送出後，後台可以收到瀏覽器推播通知（Web Push），
就算沒有開著後台網頁、甚至瀏覽器已關閉（作業系統仍在執行）也收得到，點通知會直接開啟/切到 `/admin`。

**啟用方式（每台想收通知的裝置都要各別開一次）：**
1. 用該裝置的瀏覽器打開 `/admin` 並登入。
2. 點右上角「🔔 開啟通知」，瀏覽器會跳出「允許通知」的詢問，按允許。
3. 按鈕文字變成「🔔 通知已開啟」就代表這台裝置訂閱成功了。之後可以再點一次來關閉這台裝置的通知。

**技術細節 / 限制：**
- VAPID 金鑰對（推播用的身分驗證金鑰）會在第一次呼叫時自動產生並存進 D1 的 `settings` 表，不需要另外設定，也不會每次重新產生。
- 想在 VAPID 憑證裡填自己的聯絡方式（非必要，多數推播服務商沒有強制要求），可以在 `wrangler.toml` 的 `[vars]` 加一行 `VAPID_SUBJECT = "mailto:you@example.com"`。
- 訂閱資訊存在 D1 的 `push_subscriptions` 表，每台裝置一筆；如果某台裝置的訂閱已經失效（例如很久沒開瀏覽器），推播失敗時會自動把那筆訂閱刪掉，不會一直重試。
- 每個管理員/員工帳號都可以各自在自己的裝置上開啟通知；目前設計是「有訂單就通知所有已訂閱的裝置」，沒有依帳號分別通知。
- 桌機版 Chrome / Edge / Firefox 都支援；iPhone 需要用 Safari 把 `/admin` 加入「主畫面」，改用主畫面圖示打開才能訂閱通知（iOS 16.4 以上）。
- 目前只有「會員自助下單」送出時會觸發通知；後台自己在「結帳櫃檯」建立的訂單不會通知（因為是自己建立的，不需要提醒自己）。如果之後也想在客人上傳付款證明時收到通知，可以在 `handleUploadProof` 裡比照 `handleMemberCreateOrder` 呼叫一次 `notifyAdminsOfNewOrder`（或另外寫一個通知文字不同的函式）。
- 升級既有資料庫記得跑一次 `migrate_v4.sql`（`wrangler d1 execute checkout_db --file=./migrate_v4.sql`）。全新安裝用最新的 `schema.sql` 就已經包含這張表了。

## 會員帳號密碼的用途
帳號/密碼由後台「會員管理」新增、修改（密碼是加鹽 SHA-256 雜湊，不是明文存放）。
會員可以拿這組帳密到 `/member` 頁面自己登入，查詢自己的訂單記錄與付款狀態（唯讀，無法自己改資料）。
如果會員帳號還沒設定密碼，登入時會提示「請洽店家開通」。

## 會員推薦碼 + 隱藏自助註冊連結（本次新增）
- 每位會員（不論是後台新增或自行註冊）都會自動產生一組專屬的 6 碼推薦碼（例如 `A3F92K`），避開容易混淆的 0/O/1/I/L。
- 既有會員在升級後第一次被讀取（後台「會員列表」或自己登入 `/member`）時會懶惰補上推薦碼，不需要額外跑資料轉換。
- 後台「會員列表」每一列都有「複製邀請連結」按鈕，複製的連結格式是 `你的網域/member/register?code=推薦碼`。
- 會員自己登入 `/member` 後，畫面最上方會看到自己的推薦碼卡片，一樣可以直接複製邀請連結分享出去。
- `/member/register` 是一個**沒有放在任何選單或導覽列上的隱藏頁面**，只能透過分享出去的邀請連結（帶 `?code=`）或直接輸入網址進入；`public/robots.txt` 本來就整站 `Disallow: /`，所以也不會被搜尋引擎收錄。
- 在這個頁面填寫姓名、帳號、密碼、手機（選填）並填對某位會員的推薦碼，就能自己建立會員帳號並直接登入 `/member`；推薦碼填錯或帳號重複都會擋下並顯示錯誤訊息。
- 新會員會記錄是被哪位會員推薦加入的（`referred_by`），可在後台會員列表的「推薦人」欄位看到。
- 升級既有資料庫記得跑一次 `migrate_v5.sql`（`wrangler d1 execute checkout_db --file=./migrate_v5.sql`）。全新安裝用最新的 `schema.sql` 就已經包含這兩個欄位了。
- 目前自助註冊「一定要」填推薦碼才能建立帳號（沒有推薦碼就無法註冊），如果之後想開放不需要推薦碼也能註冊，把 `handleMemberRegister` 裡「推薦碼找不到會員就擋下」那段邏輯改成允許 `referred_by` 為 `null` 即可。

## 最低購買金額 200 元（本次新增）
- `/member` 頁面的「查價專區」與「自助下單」現在共用同一個最低金額門檻：**200 元**（原本查價是 150 元，自助下單本來沒有限制），上限維持 50000 元不變。
- 查價專區：金額輸入框的提示文字、瀏覽器 `min` 屬性都已改成 200；輸入低於 200 元會跟原本超過上限一樣，被歸類為「超出範圍」並提示改私訊詢問。
- 自助下單：
  - 快速金額按鈕把原本的「$100」改成「$200」（因為 100 元已經低於新的門檻），其餘 $300 / $500 / $1000 / 其他金額不變。
  - 前端輸入框加上「最低 200 元」提示與 `min="200"`；送出前若金額低於 200 元會擋下並提示錯誤。
  - **後端 API（`POST /api/member/orders`）也加了同樣的檢查**，就算有人繞過前端直接呼叫 API，金額低於 200 元一樣會被拒絕（回傳 400 錯誤）。
- 門檻數字整理成共用常數：前端在 `templates.js` 的會員頁 `<script>` 裡是 `MIN_QUOTE_AMOUNT`；後端則是 `functions/_lib/rates.js` 匯出的 `MIN_QUOTE_AMOUNT`，被 `functions/[[path]].js` 引入為 `MIN_ORDER_AMOUNT` 使用。以後如果要再調整最低金額，建議統一改這兩個地方的常數就好。
- **注意範圍**：這次調整只套用在會員自己在 `/member` 使用的「查價」「自助下單」；後台「結帳櫃檯」（店家幫客人手動建立訂單）目前刻意保留無金額下限，方便店家彈性處理小額訂單或補單。如果也想套用到後台結帳櫃檯，需要另外調整 `handleCreateOrder`。
- 這次調整不涉及資料庫結構，**不需要跑任何升級腳本**。

## 系統公告彈窗（本次新增）
- 會員登入 `/member`（含重新整理後自動恢復登入狀態）時，若後台有啟用公告，會立即跳出彈窗。
- 後台「系統公告」頁籤可設定：
  - 是否啟用
  - 公告標題（選填）
  - 公告類型：**文字公告**，或 **圖片輪播**（可上傳多張圖片，會員畫面會自動輪播，並可用左右箭頭／小圓點手動切換）
  - 可按「預覽」直接在後台看到彈窗大致樣式，不需要真的登入會員頁面測試
- 會員畫面的彈窗有兩個按鈕：
  - 「了解」：關閉彈窗，但下次登入（或重新整理）還是會再看到
  - 「今天不再顯示」：當天不會再彈出（存在該會員瀏覽器的 `localStorage`，換裝置或清除瀏覽器資料就不會記得）
  - 只要後台重新按過「儲存」（不論內容是否有改），就會視為新的一次公告，即使會員今天已經按過「今天不再顯示」，下次登入也會再彈出一次
- 公告內容存在既有的 `settings` 資料表（key 為 `announcement`，value 是 JSON 字串），**不需要額外跑資料庫升級腳本**
- 圖片一樣是以 base64 直接存進 D1（跟條碼圖片、付款證明的做法相同），建議每張控制在 500KB 以內、最多 10 張，避免設定值過大
- 目前只有 `/member` 會彈出公告；`/admin` 後台本身沒有這個彈窗

## 優惠碼功能（本次新增）
後台新增「優惠碼」頁籤，可以建立、編輯、停用、刪除優惠碼；結帳櫃檯（店家手動建單）與會員自助下單都可以在下單時輸入優惠碼折抵金額。

**優惠碼可設定的條件：**
- **折扣百分比**：例如設 `10` 表示折抵訂單金額的 10%（無條件捨去到整數）
- **最高優惠金額**：折抵金額的上限（例如折扣算出來是 $150，但設定上限 $100，實際只折 $100）；留空表示不限
- **最低使用金額**：訂單金額需達到這個門檻才能使用此優惠碼；留空或 0 表示沒有門檻
- **使用次數上限**：這組優惠碼總共可以被使用幾次（不分會員，所有人共用同一個上限）；留空表示不限次數
- **到期時間**：超過這個時間後優惠碼自動失效；留空表示永久有效（除非手動停用）
- **啟用 / 停用**：可以隨時停用一組優惠碼而不用刪除，之後要重新開放時直接切回啟用即可

**使用流程：**
- 結帳櫃檯與會員自助下單的表單都有「優惠碼」輸入框 + 「套用」按鈕，按下去會呼叫 `POST /api/coupons/preview` 試算折抵金額並顯示（純試算，不會真的扣用次數），方便下單前先確認。
- 真正送出訂單（`POST /api/admin/orders` 或 `POST /api/member/orders`）時如果有帶 `coupon_code`，後端會重新驗證一次（因為前台試算跟實際送單中間可能有時間差，例如優惠碼在這期間被別人用完、被停用、或剛好過期），驗證通過才會：
  1. 把該筆訂單的 `amount` 存成**折抵後的金額**（也就是這筆訂單實際要收的錢，後續轉帳/條碼/儲值統計/月報表都是用這個折抵後的金額）
  2. 額外把 `original_amount`（折抵前原始金額）、`coupon_code`（使用的優惠碼，存快照，之後就算優惠碼被改名或刪除也不影響這筆訂單的歷史記錄）、`coupon_discount`（實際折抵金額）存進這筆訂單
  3. 該優惠碼的已使用次數 `used_count` +1
- 後台「訂單列表」新增「優惠」欄，顯示這筆訂單用了哪個優惠碼、折了多少錢；`/pay/{token}` 付款頁與會員「我的訂單記錄」也會顯示原始金額與折抵金額的明細。
- 月報表 CSV 匯出新增「原始金額」「優惠碼」「折抵金額」「實付金額」欄位。

**注意事項：**
- 一筆訂單只能使用一組優惠碼，不支援疊加多組優惠碼。
- 折扣目前只支援「百分比」，不支援「固定金額折扣」；如果之後想加固定金額折扣，可以在 `coupons` 表加一個 `discount_type` 欄位，並在 `helpers.js` 的 `applyCouponToAmount()` 裡依類型分開計算。
- 訂單建立後如果透過後台「更正」功能手動改動金額，不會連動重新計算優惠碼折抵（更正屬於人工覆蓋，優惠碼欄位會維持原本記錄的值，僅金額會被覆蓋），使用上請留意。
- 刪除一組優惠碼不會影響已經使用過它的歷史訂單記錄（訂單裡存的是優惠碼字串快照，不是外鍵關聯）。
- 升級既有資料庫記得跑一次 `migrate_v6.sql`（`wrangler d1 execute checkout_db --file=./migrate_v6.sql`）。全新安裝用最新的 `schema.sql` 就已經包含這張表跟這三個欄位了。

## 其他備註（與 Workers 版相同）
- 轉帳／超商條碼／台灣Pay 目前都是後台人工核對後按「標記已付款」；付款證明（截圖／末幾碼）只是輔助核對，不會自動改變訂單狀態。
- 月報表用 CSV（Excel 可直接開啟，中文不亂碼），非真正的 `.xlsx`；CSV 已包含「訂單完成(結案)」與「付款證明末幾碼」欄位。
- 條碼圖片、付款證明截圖目前都直接以 base64 存進 D1，適合中小流量；量大建議改存 R2。
- 「訂單更正」與「訂單完成」互斥：已結案的訂單要先按「取消結案」才能再更正金額/會員/付款方式。
